# 決定事項: プラットフォーム構成方針(2026-08-19)

## 基本方針(確定)

1. **現状の Kintone はマスタ(データベースの正)として活用**する
2. **Excel や外部帳票で運用しているものは Google ベースの仕組みに集約**する
   (部屋管理表、清掃スケジュール表、Monthly Report 等)
3. **Kintone の API 連携を活用して Google 側データとの連携**を図る

## 現行 Kintone アプリ構成(提供された構成図より)

### アプリ一覧と関連キー

| アプリ | 関連 | 結合キー |
|---|---|---|
| オーナー情報 | オーナー請求管理 | 施設名 |
| 〃 | オーナーやり取り情報 | オーナー氏名 |
| 〃 | 客室情報 | (親子) |
| 客室情報 | オーナーやり取り情報 | 施設名&部屋番号(客室情報) |
| 〃 | ToDoリスト | 施設名&部屋番号 |
| 〃 | お客様現金やり取り | 施設名&部屋番号 |
| 〃 | RCR | 物件名職称 |
| 〃 | OLS物件保険管理表 | 施設名&部屋番号 |
| 〃 | 入退去・見学履歴 | (経由) |
| 入退去・見学履歴 | 顧客データベース | 宿泊者氏名 |
| 顧客データベース | 保証金管理 | 入退去・見学履歴レコード |
| 物件情報 | (独立・リレーションなし) | — |

### 現行構成から読み取れる論点

- **予約・滞在の「未来」を持つアプリがない**: 「入退去・見学履歴」は実績(過去)の記録であり、
  将来の予約・滞在予定は Excel 部屋管理表が事実上の台帳になっている
- 顧客との結合キーが「宿泊者氏名」、客室との結合キーが「施設名&部屋番号」の文字列結合であり、
  表記ゆれに弱い(将来的にはレコードID参照への移行が望ましい)
- 「物件情報」アプリが独立しており役割が不明(要ヒアリング)
- 清掃管理に対応するアプリがなく、Excel(清掃スケジュール表)のみで運用されている
