## 既存資産「見積もりくん」(GAS)の構造

- 見積もり情報: 見積番号 / 顧客名 / 部屋名 / 契約開始日・終了日・日数 / ペット有無 / 金額 / ステータス
- **部屋マスタ**: 部屋名(例: UR310_アルトゥーレ美浜)/ 間取り / 基本料金(日) / 清掃費 / 1ヶ月家賃
- **シーズン料金マスタ**: 冬期 +2,000円/日、冬季ピーク +3,000円/日、夏ピーク +3,000円/日、
  夏トップ +6,000円/日(設備車料金の加算も別立て)
- **保証金・手数料マスタ**:
  - 保証金: 1〜30日=3万円、31〜59日=6万円、60日以上=1ヶ月家賃
  - 追加清掃費: 90〜364日=22,000円、365日以上=44,000円
  - 手数料: 1〜5ヶ月=44,000円、6〜12ヶ月=66,000円

→ **料金計算エンジンの原型が既に Google 基盤(GAS)上に存在する**。新システムの料金マスタはここから発展させられる。

## 業務フローから読み取れる主要な実態

### ① 予約窓口

- 問い合わせ(Webフォーム/電話)→条件案内(予約表参照)→見積(見積もりくん)→申込(Word手作成)
  →オーナー確認→入金案内→契約書雛形→予約確定→予約表記入→サイボウズ(入居/退去日)→Kintone顧客登録
- 課題: リード情報の蓄積なし / 空室検索が手作業 / 請求書・領収書の発行が手動で不統一 / 海外顧客の個別ルール多数
- ダブルブッキング対策: 予約表に「案内中」と記載する運用

### ③ 清掃

- 毎月25日に翌月分の清掃計画を策定。予約と予約の隙間日を目視で探して清掃日を決定
  → 顧客に日時確認(手動メール、自動化希望)→ 業者調整 → 予約表・サイボウズスケジュールへ転記
- 定期ハウスキーピング(曜日・時間固定)はサイボウズが詳細情報を持つ

### ④ 月次業務【A】= MR 作成の実態(最重要)

- フロー: **元データ(相殺リスト)を社内で作成 → 田中さん(外部)へ渡す → 田中さんがレポート・請求書作成**
- MR のローデータは**予約表から関数で生成。Kintone には保管していない**
- 相殺リストはスプレッドシート。ソースは「予約表を見る方法」+「オーナー請求管理アプリ」の2系統
- 色分け運用: ピンク=未相殺、黄色=MR反映済み(相殺済み)
- 還付項目例: 清掃代、ゲストルーム利用料、駐車場代(予約リスト→相殺リストへ転記運用)
- オーナー請求金額は契約で決まっており、赤字でも OK。原価レコードの管理・計算は残していない

### ⑤ RCR / ⑥ 退去 / ⑦⑧ スポット

- RCR: 予約表と RCR アプリを見て対応メンバーと日程をアサイン → 実地対応と実績入力。
  予約表と Kintone の突き合わせが必要
- 退去: ToDo リスト(Kintone)→ 保証金返金(保証金アプリ、現金パターンは小口現金で煩雑)→ 清掃(Excel)
- スポット: Teams チャットチャンネルで管理、オーナー請求は Kintone アプリ

### ⑨ 新規オーナー

- Teams で管理、賃料査定・シミュレーションは都度 Excel。管理の仕組みが分散
- 契約時に Kintone(客室情報・物件情報・オーナー情報)へ登録 ← **「物件情報」アプリはここで使用**
