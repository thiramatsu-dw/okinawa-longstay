提供された資料から読み取れた現状業務の整理。

> リポジトリには原本をコミットせず、構造の分析結果のみを記録している。

## 事業モデル(資料からの推定)

- マンスリーマンション/ロングステイ向け客室の**転貸(サブリース)運用**。
  オーナーから客室を預かり、利用者へ貸し出し、賃料をオーナーへ分配する。
- 管理客室数: **約126室**(2025年8月時点の部屋管理表より。棟は「UR(アルトゥーレ美浜)」ほか)
- 料金区分: **レギュラー / 冬期 / ピーク / トップ**(季節変動)+ **イヤリー(年間)** + **オーナー様利用**
- オーナー分配: 転貸賃料の **70%**(イヤリーは75%)+ 光熱費(例: 1,200円/日 × 日数)。
  毎月「Monthly Report」を物件・オーナーごとに作成し、請求額(排水管清掃積立会等)を相殺して振込。

## 現状の業務ツール(Excel 2種 + 帳票)

### 1. 部屋管理表(月別シート型 Excel)★基幹台帳

- ブック構成: `mother`(マスタ/原本)+ 月別シート `202001`〜`202512`(毎月コピーで増殖)
- 行 = 客室(約126室)。左側に物件属性: 施設名 / 部屋NO / 備考 / 間取 / 平米 / 収容人数 / 和室・布団 / ベッド構成 / 駐車場NO
- 列 = 当月の日(1〜31、曜日付き)。**セルに数値コードで稼働状況を記録**:
  - 現行運用は「30」「40」「50」のみ(注記より)
    - `30` = マンスリー利用(月極)/ `40` = 長期(年間・イヤリー)/ `50` = オーナー利用
  - 旧コード体系: 11/12/13(WEEK日割 レギュラー/ピーク/トップ)、31/32/33(月 日割・ピーク・トップ)、41(長期日割)
  - 文字も混在: 「チ」(チェック?)、「通」(通常清掃?)、「排水管清掃」「内覧」「オーナー利用中」等のメモ
- 右側列: 備考(入退去予定・商談メモの自由記述)、ベッドメイク、「IN前」チェック等
- 課題(推定): 月別シートのコピー運用、セルコードと自由記述の混在、集計・検索・履歴管理の限界

### 2. 清掃スケジュール表(月別シート型 Excel)

- ブック構成: 「最新データベース※触るな」(原本)+ 月別シート(6月〜、命名が不統一: `7月` `2025.8` `202510` 等)
- 清掃種別: **お客様退去清掃 / リクエスト清掃 / イン前チェック / 空室管理 / 運用前清掃**
- 列: 部屋 / 間取り / 平米数 / 退去日 / 入居日 / 担当 / 清掃日 / 清掃区分 / ベッドメイク・備品補充 / 備考
- 付帯管理: 鍵・スリッパ・リモコンキーの貸出日・サイン・返却日・サイン(清掃業者への鍵受け渡し管理)

### 3. Monthly Report(オーナー向け月次運用報告書)

- 物件(部屋)× オーナー × 月ごとに作成・送付
- 内容:
  - 年間運用状況カレンダー(日別に料金区分を色分け: レギュラー/冬期/ピーク/トップ/イヤリー/オーナー様利用)
  - 当月運用金額・入金予定日・振込口座
  - 利用者から受領した転貸賃料(区分別日数×単価 + 光熱費)
  - 賃料(オーナー分 70%/イヤリー75% + 光熱費)= 小計(A)
  - ご請求金額(前月繰越、排水管清掃積立会等、消費税)= 小計(B)
  - 相殺 (A)−(B) = 振込額、年間累積運用額、月別入金実績
- 現状は Excel で手作成と推定(帳票自動生成が明確な効率化ポイント)

## 将来システム構想(Kintone用アプリ設計案 Ver011 より)

社内で既に Kintone を前提としたアプリ構成案が検討されている。
構想されているアプリ(≒ドメイン)一覧:

| アプリ/機能 | 概要 |
|---|---|
| 客室管理 | 客室マスタ |
| オーナーマスタ | オーナー情報 |
| 清掃業者マスタ | 清掃業者情報 |
| 滞在管理 / 滞在履歴管理 | 予約・滞在(現在/過去) |
| 問い合わせ管理 | 問い合わせ→空室提案(スタート地点) |
| 見積管理 | 見積書発行・メール送付 |
| 請求管理 | 請求書発行・メール送付 |
| タスク管理 | 清掃手配・滞在中/退去後タスク、返答内容管理 |
| 客室別清掃日管理 | Webフォーム(ハウスクリーニング候補日調整/清掃候補日調整)と連携 |

### 優先度1: 客室スケジュールボード

- 部屋ごとの予約・滞在・清掃・提案のスケジュールを**横並び(部屋×日マトリクス)で閲覧**
- フィルタ: 表示期間 / エリア / 宿泊人数 / 空室のみ → 「この期間で空いている物件」を抽出し提案までの時間を短縮
- フロー: 問い合わせ → 空室提案 → 清掃手配 → 滞在中タスク → 退去後タスク を一本化

### 優先度2: タスク&CRM一元管理(カンバン)

- ステータス(未着手/進行中/完了、提案中/クロージング等)を任意の切り口でカンバン表示
- 問い合わせ・滞在・オーナー等のレコードにタスクを紐付け、メール送信も組み合わせ
- 「誰が休んでも業務が止まらない」運営体制が目的

### その他の構想

- 滞在レコード(入居/RCR/スポット/退去)から料金を集計 → 段階1(洗い出し)→ 段階2(相殺リスト)→ オーナーへ**月次レポート/請求(PDF・Excel)自動生成**
- 清掃業者との調整: 清掃候補日一覧をメール送信 → 外部Webフォームで回答 → 自動登録
- 宿泊者からのハウスキーピング依頼: 外部フォーム受付 → 清掃業者へ連絡 → 候補日回答
- HubSpot連携: 提案後未返信の追客(ステップメール)、最新空き情報の配信
