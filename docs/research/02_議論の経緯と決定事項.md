## 資料1: ディスカッション資料「事業拡大に向けた基幹システム刷新プロジェクト」(2025-12-05)

### 背景・目標

- 現在100件強の物件を運用。Excel と Kintone の分散管理で業務が煩雑化
- まず **200室体制** を目指す(将来ビジョンは3000室 → 資料2参照)
- 中期滞在(1ヶ月〜数ヶ月)市場が拡大中。当社は「沖縄の人気物件の保有+丁寧な運用代行」が強み
- ベンチマーク: Blueground(米国)。B2B特化・垂直統合・Tech活用
- ビジネスモデル: オーナーから物件を預かり運用代行手数料(売上の30%)を受領
- USP: アルトゥーレ美浜など人気物件の大量保有 / OTA非依存の直販体制 / レンタカー等「住+α」のセット提供

### 顕在化している業務課題(11項目)

|---|---|---|---|

### 方針決定

- パッケージ(AirHost等)は短期滞在向けで「物件検索」「付帯設備管理」「オーナー管理」「CRM」が不足。
  OTA連携も不要なため強みを活かせず、部屋数従量課金でコスト高になる構造
- **結論: Kintone をデータベース中核とした「スクラッチ拡張開発」を採用**(プラグイン+API連携)
- 残論点: 予算感、どこまでの機能をいつまでに実装するか

## 資料2: Web会議議事録(2026-07-10、Gemini自動生成)

### 基本方針

- **「20名で3000室を管理」** を長期目標に、各業務セクションに AI パートナーを配置
- 完全自動化を一足飛びに行わず、**個別業務の最適化を積み重ねる**アプローチ
- 新ツールを増やさず、**既存プラットフォーム(Kintone・Gmail・Teams)を連携して活用**
- 開発はアジャイル。訪問初日に大枠決定 → プロトタイプ → フィードバックで修正

### 初回着手領域(合意)

1. **顧客対応・予約業務**: 条件指定で空室を算出するチャットボット形式から検証開始
2. **予約表(部屋管理表Excel)の仕組み見直し**: 手動確認の手間を削減する新しい管理方法
3. **予約確定後の照合作業の自動化**: 金額・項目の突合を AI がルール学習し「はい/いいえ」判定
4. **マンスリーレポート(MR)自動化**: Kintone からデータ抽出 → スプレッドシート/PDF 変換 → 自動送信

### システム構成の論点(未確定)

- Kintone ベース開発 か、Claude Code による独自スクラッチ開発かの選択肢を提示
- まずは現環境で予約表等の自動化を進めつつ、将来の拡張性・独自サーバー構築も視野に検討継続

### 将来要件

- **民泊事業への参入予定**: 稼働率増、OTA 連携、ダイナミックプライシング対応が必要になる
- 開発環境: Claude Code 用 PC(Mac)+ Splashtop リモートアクセス、Google Workspace アカウント
